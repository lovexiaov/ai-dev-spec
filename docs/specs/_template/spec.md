# Spec: <特性名称>

> 复制 `docs/specs/_template` 为 `docs/specs/<feature>/` 后填写。
> 这是 Agent 的「契约与唯一事实来源」，必须**可测**、**正向定义**为主。

## Goal（目标）
- 用 1–3 句话说明：为谁、解决什么、成功长什么样。
- 例如：让用户在 30 分钟内通过限时限邮件链接重置密码。

## Non-goals（非目标）
- 明确**不做**什么，阻止 Agent 过度构建与范围蔓延。
- 例如：本期不做短信/社交登录恢复；不动现有 session 模型。

## Constraints（约束）
- 必须遵守的架构/安全/合规/性能限制与数据契约。
- 例如：重置 token 30 分钟过期、单次使用、哈希存储；复用现有邮件服务接口。

## Interfaces（接口 / 数据契约）
- 给出具体请求/响应示例与错误码，尽量用机器可读契约（OpenAPI / JSON Schema / TS 类型）。
- 例如：`POST /auth/reset-request { email } -> 202`（无论邮箱是否存在，均防枚举）。

## Acceptance Criteria（可测验收条件）
> 每条都应是「测试能验证」的断言，而非形容词。

- [ ] `reset-request` 对任意邮箱均返回 202，不泄露用户是否存在。
- [ ] 合法未过期 token 可设新密码并返回 200。
- [ ] 过期 token 返回 410 且不改密码。
- [ ] 复用 token 返回 400。
- [ ] 新密码须通过现有复杂度策略。

## Done when（完成定义）
- 所有验收测试通过；边界情况覆盖；相关文档（含本 spec）已更新；`traceId` 已贯穿该链路。
